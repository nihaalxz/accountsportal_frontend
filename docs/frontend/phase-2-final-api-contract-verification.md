## Mismatch Audits

1. **Transaction Reversal**: NOT SUPPORTED by backend API. Handled inside the frontend using a static disclaimer/warning screen for transactions in approved state.
2. **Transaction Concurrency (RowVersion)**: The backend database does not use SQL Server `RowVersion` bytes for optimistic concurrency checks on bank/account resource edits. Instead, concurrency conflicts bubble up directly as a 409 status on transaction posting/modification when state transitions are invalid (e.g. attempting to approve a transaction that is no longer pending). The frontend properly maps these 409 codes to the `ConflictDialog` UX.
3. **Single Transaction Detail API**: No endpoint `/api/transaction/{id}` exists. The detail page uses the list endpoint with a pre-fetched buffer to search client-side, showing a 404 UI if the ID is missing.
